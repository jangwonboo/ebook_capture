# Markdown Reader — 편집 모드 기획 (WYSIWYG Markdown 편집기)

기준일 2026-11-25. 상태: **PoC A(Vditor 즉시 렌더링) 구현·검증 완료**, 2단계 일부(장 편집·저장·원본 보호) 동작. 결과는 §13. 리더 전체 스펙은 [SPEC.md](SPEC.md), 사용법은 [README.md](README.md).

리더에서 읽다가 문단·단락·제목·표·수식·차트를 바로 고치고, 결과를 책의 `.md` 파일에 저장한다. 화면에서는 렌더링된 모양 그대로 편집하고(WYSIWYG), 파일은 Markdown으로 남는다.

---

## 1. 왜 필요한가

OCR로 만든 책에는 사람이 손봐야 할 곳이 남는다. 지금은 Typora나 VS Code로 `.md`를 따로 열어 고친다.

| 실제로 나오는 것 | 예 |
| --- | --- |
| 잘못 끊기거나 붙은 문단 | 쪽 경계에서 끊긴 문단, 한 문단 안에 섞인 그림 캡션 |
| 제목 등급 오류 | 그림 제목이 `###`로 섬, 차례의 `03 부`가 제목으로 남음 |
| 본문으로 떨어진 제목 | "인생이 넓어지려면깊어져야 한다" (띄어쓰기도 빠짐) |
| OCR 오탈자 | "‘어" + "평게" → "어떻게" |
| 수식·표 확인 | 머신러닝 입문 수식 블록 134개, 마스터링 트랜스포머 HTML 표 30개 |

리더는 지금 `$$` 수식과 HTML 표를 렌더링하지 못하고 원문 글자로 보여 준다. 편집 기능을 넣으려면 렌더링부터 맞춰야 한다(§5).

---

## 2. 목표와 비목표

목표:

- 읽던 자리에서 바로 편집 모드로 들어가, 보이는 모양 그대로 고친다
- 문단 합치기·나누기, 줄 잇기, 제목 수준 변경, 블록 이동을 한 번에 한다
- 수식, 표(병합 셀 포함), 코드, 그림, 차트를 렌더링된 상태로 보고 편집한다
- 결과는 책 폴더의 `{title}.md`에 Markdown으로 저장한다. 고치지 않은 부분은 한 글자도 바뀌지 않는다
- 원본을 잃지 않는다: 첫 저장 전에 원본을 따로 두고, 저장마다 되돌릴 수 있다

비목표:

- 범용 문서 편집기(새 문서 작성, 협업, 클라우드 동기화)
- Markdown 문법 밖의 서식(글자 색, 글꼴 크기 지정, 자유 배치)
- PDF·DOCX 내보내기 (필요하면 Markdown에서 별도 도구로)

## 3. 편집 방식

### 3.1 편집 단위: 장

리더는 장(`##` 이하) 하나를 한 화면에 보여 준다. 편집도 장 단위로 한다.

- 상단의 **편집** 버튼(또는 `E`)을 누르면 지금 장이 편집기로 바뀐다
- 편집기에는 그 장에 해당하는 Markdown 구간만 들어간다. 300KB짜리 책 전체를 한 편집기에 넣지 않아 빠르고, 저장할 때 다른 장은 건드리지 않는다
- 저장하면 파일에서 그 구간만 바꿔 끼운다. 이를 위해 파서가 장마다 원문 줄 범위(`sourceStart`, `sourceEnd`)를 기록한다
- 다른 장으로 넘어가거나 편집을 끝낼 때, 저장하지 않은 변경이 있으면 저장·버리기·취소를 묻는다

### 3.2 한 창에서 편집과 렌더링

편집 창은 하나다. 화면은 늘 렌더링된 모양이고, 고치는 곳만 그 자리에서 원문으로 바뀌었다가 커서가 떠나면 다시 렌더링된다(Typora 방식). 원문 창과 미리보기 창을 나란히 두지 않는다.

| 대상 | 평소 | 커서가 들어오면 | 커서가 떠나면 |
| --- | --- | --- | --- |
| 문단·목록·인용 | 렌더링된 글 | 그대로 입력. 굵게·기울임·링크는 커서가 그 글자 안에 있을 때만 `**`, `[ ]( )` 기호를 보여 줌 | 기호 숨김 |
| 제목 | 렌더링된 제목 | 앞에 `##` 표시, 지우거나 늘려 수준 변경 | 렌더링 |
| 인라인 수식 `$…$` | KaTeX | 그 자리에서 `$…$` 원문으로 펼침, 바로 위에 작은 미리보기 | KaTeX |
| 별행 수식 `$$` | KaTeX | 블록이 원문 칸으로 펼쳐지고, 칸 바로 아래에 실시간 미리보기 | KaTeX |
| 파이프 표 | 표 | 원문으로 바꾸지 않고 칸을 직접 편집. 행·열 메뉴 | 표 |
| HTML 표, 다이어그램, 차트, 코드 | 렌더링 | 블록이 원문 칸으로 펼쳐지고 아래에 미리보기 | 렌더링 |
| 그림 | 이미지 | 설명·경로 칸 표시 | 이미지 |

- 블록 이동: `↑`/`↓`로 블록 경계를 넘으면 다음 블록으로 들어간다. 수식·표 블록은 `Enter`로 들어가고 `Esc`로 나온다
- 렌더링이 실패한 블록(문법 오류 수식 등)은 원문으로 보이고 빨간 표시가 붙는다. 저장은 쓴 그대로 한다
- **원문 보기**는 전환 버튼 하나로 남긴다. 장 전체를 Markdown 텍스트로 보는 비상구다. 블록을 많이 옮기거나 문법이 꼬였을 때 쓴다. 나란히 보기는 두지 않는다

### 3.3 리더 화면과의 관계

- 리더의 "끊긴 글 복원"(SPEC §4.3)은 화면에서만 문단을 이어 보여 준다. 편집 모드는 파일 원문을 그대로 보여 주고, 복원 규칙이 이으려는 자리를 **제안 표시**로 띄운다. 한 번 눌러 적용하면 파일에 반영된다(§4.2)
- 편집 중에는 주석 패널을 읽기 전용으로 두고, 칠한 표시는 숨긴다. 저장 후 주석 위치를 다시 찾는다(§7.3)
- 왼쪽 목차는 저장할 때 다시 만든다. 제목을 바꾸면 트리에 바로 반영된다

## 4. 편집 기능

### 4.1 문단·단락 조정 (1순위)

| 기능 | 동작 | 단축키 |
| --- | --- | --- |
| 다음 문단과 합치기 | 두 문단을 하나로. 이음새 띄어쓰기는 복원 규칙(책 낱말 목록)으로 정하고, 바로 바꿀 수 있게 커서를 이음새에 둔다 | `Ctrl+Shift+J` |
| 여기서 나누기 | 커서 위치에서 문단을 둘로 | `Enter` |
| 줄 잇기 | 한 문단 안의 줄바꿈을 모두 지움 | |
| 블록 위/아래로 옮기기 | 문단·그림·표 단위로 이동 | `Alt+↑/↓` |
| 블록 종류 바꾸기 | 본문 ↔ 제목(`##`~`####`) ↔ 인용 ↔ 목록 ↔ INSIGHT 카드 | `Ctrl+1~4`, `Ctrl+0` |
| 제목 합치기 | 두 줄로 나뉜 제목을 하나로 | |
| 블록 지우기 | 선택한 블록 삭제 (되돌리기 가능) | |

### 4.2 끊긴 글 제안

편집 모드에 들어가면 그 장에서 복원 규칙이 찾은 곳을 여백에 표시한다.

- 쪽 경계에서 끊긴 문단 → "잇기" (붙임/띄움 미리보기)
- 두 줄로 나뉜 제목, 제목 앞에 떨어진 구절 → "합치기"
- 하나씩 적용하거나 "이 장 모두 적용"으로 한꺼번에 적용한다
- 적용한 결과는 파일에 남으므로, 그 뒤로는 리더의 화면 복원이 할 일이 없다

### 4.3 찾아 바꾸기

- 이 장 / 책 전체 범위, 정규식 선택
- 책 전체 바꾸기는 바뀔 곳 목록을 먼저 보여 주고 고른 것만 적용한다 (예: OCR이 일관되게 틀린 "맴리듀스" → "맵리듀스")
- 바꾼 내역은 `ocr_typos.txt` 형식으로 내보낼 수 있다. 파이프라인 사전에 넣으면 다음 책부터 자동으로 고쳐진다

### 4.4 인라인 서식

굵게(`Ctrl+B`), 기울임(`Ctrl+I`), 인라인 코드(`` Ctrl+` ``), 링크(`Ctrl+K`), 인라인 수식(`Ctrl+M`). Markdown에 있는 것만 둔다.

## 5. 블록별 렌더링과 편집

먼저 리더 읽기 화면부터 이 렌더링을 갖춘다(편집 없이도 수식·표가 제대로 보이도록). 편집기도 같은 렌더러를 쓴다.

| 블록 | Markdown 표기 | 렌더링 | 편집 |
| --- | --- | --- | --- |
| 문단·제목·목록·인용 | 표준 | 지금과 같음 | WYSIWYG 직접 입력 |
| 인라인 수식 | `$…$` | KaTeX | 누르면 작은 원문 칸 + 미리보기 |
| 별행 수식 | `$$` 별도 줄 + 내용 + `$$` (파이프라인 형식, `\begin{aligned}` 포함) | KaTeX 표시 모드 | 블록 안 원문 칸 + 실시간 미리보기. 문법 오류는 빨간 표시, 파일에는 쓴 그대로 저장 |
| 파이프 표 | GFM `\| … \|` | 표 | 칸 직접 입력, 행·열 추가/삭제/이동, 정렬. `\|` 이스케이프 유지 |
| HTML 표 (병합 셀) | `<table>…</table>` (파이프라인이 rowspan/colspan 있을 때 냄) | 정리된 HTML 표 (허용 태그만, §8.2) | 1차: 원문 칸 + 미리보기. 2차: 칸 병합·분할 가능한 표 편집기, 저장은 HTML로 |
| 코드 | ` ``` ` 펜스 + 언어 | 고정폭, 언어별 색 | 블록 안 원문 편집 (탭·들여쓰기 유지) |
| 그림 | `![설명](assets/…)` | 이미지 + 캡션 | 설명 수정, 교체, 끌어다 놓아 추가(§6.3) |
| 다이어그램 | ` ```mermaid ` | Mermaid | 원문 칸 + 미리보기 |
| 데이터 차트 | ` ```chart ` + JSON (§5.1) | 차트 | 표 형태 데이터 편집기 + 종류(막대·선·원) 선택, 원문 JSON도 편집 가능 |
| INSIGHT 카드 | `#### INSIGHT` + 다음 블록들 | 카드 | 카드 안 블록을 일반 블록처럼 편집 |
| 각주·HTML 조각 | 그 외 원문 | 원문 그대로 표시 | 원문 칸. 모르는 문법은 건드리지 않고 보존 |

수식 경계 규칙: 코드 블록·인라인 코드 안의 `$`, 셸 프롬프트(`$ echo …`), 금액(`$5`)은 수식으로 보지 않는다. 실제 책(머신러닝 입문)에 셸 명령 줄과 인라인 수식이 섞여 있어 회귀 테스트로 둔다.

### 5.1 차트 표기

Markdown에는 표준 차트 문법이 없다. 두 가지만 지원한다.

- 다이어그램(흐름도, 순서도): ` ```mermaid ` — GitHub 등 다른 뷰어에서도 렌더링된다
- 데이터 차트: ` ```chart ` 펜스 안에 JSON

  ```json
  { "type": "bar", "title": "모델별 추론 시간", "labels": ["bert-base", "distilbert"],
    "series": [{ "name": "batch 4", "data": [0.12, 0.06] }] }
  ```

  우리 리더에서만 차트로 보이고, 다른 뷰어에서는 JSON 코드 블록으로 보인다(내용은 읽힘). 편집 엔진을 Vditor로 정하면 Vditor 내장 형식인 ` ```echarts `(ECharts 옵션 JSON)를 쓰고, 위 형식은 쓰지 않는다(§9 결정 3)

표에서 차트 만들기: 표를 선택하고 "차트로" → 첫 열을 라벨, 나머지 열을 계열로 한 ` ```chart ` 블록을 표 아래에 추가한다. 원래 표는 그대로 둔다.

## 6. 저장

### 6.1 저장 위치와 형식

- 저장 대상은 "폴더 열기"로 연 책의 `{title}.md`. 브라우저 폴더 쓰기 권한이 필요하다(Chrome·Edge)
- "파일 열기"로 연 책은 편집은 되지만 저장은 "다른 이름으로 내려받기"만 된다. 주석처럼 "폴더로 저장 전환"을 제공한다
- 줄바꿈 LF, UTF-8, 파일 끝 줄바꿈 하나 (파이프라인 출력과 같게)

### 6.2 원본 보호

| 장치 | 내용 |
| --- | --- |
| 원본 사본 | 처음 저장할 때 한 번 `{title}.original.md`를 만든다. 이후 덮어쓰지 않는다 |
| 저장 기록 | 저장마다 `.reader/history/{title}.{시각}.md`에 직전 판을 남긴다. 최근 20개 |
| 변경 확인 | 저장 버튼 옆 "변경 보기"로 이번 저장의 바뀐 줄을 보여 준다 |
| 외부 변경 감지 | 열었을 때 이후 파일이 바뀌었으면(파이프라인 재조립, 다른 편집기) 저장 전에 알리고 고르게 한다: 내 변경으로 덮기 / 다시 읽기 / 다른 이름으로 |
| 되돌리기 | 편집 중 `Ctrl+Z`/`Ctrl+Y`. 저장 후에는 기록에서 판을 골라 되돌림 |

### 6.3 그림 추가

- 그림 파일을 편집기에 끌어다 놓거나 붙여 넣으면 `assets/<내용 해시>.<확장자>`로 복사하고 `![그림](assets/…)`를 넣는다 (파이프라인과 같은 이름 규칙)
- 같은 그림이 이미 있으면 복사하지 않고 기존 경로를 쓴다
- 그림 블록을 지워도 `assets/`의 파일은 지우지 않는다

### 6.4 캡처 파이프라인과의 경계

파이프라인을 다시 돌리면(`--text` 재조립) `{title}.md`를 새로 써서 편집이 사라질 수 있다. 막는 장치:

- 리더는 저장할 때 front matter에 `edited: true`와 마지막 편집 시각을 남긴다
- 파이프라인 조립은 `edited: true`인 `.md`를 덮어쓰지 않고 `{title}.assembled.md`로 쓴 뒤 그 사실을 알린다 (`ARCHITECTURE.md` 반영 필요)
- 파이프라인 쪽 교정(사전, `--proofread`, 쪽 경계 복원)은 그대로 둔다. 편집기는 그 결과를 사람이 마무리하는 단계다

## 7. 화면

### 7.1 편집 모드 배치

```text
┌ 상단: ☰ Markdown Reader · 책 제목 ······ [읽기|편집] · 저장 ● · 변경 보기 · ⚙ ┐
├ 목차 (편집 중 장 강조) ┬──────────── 편집기 ────────────┬ 제안 / 주석(읽기 전용) ┤
│                        │ [편집 | 원문 보기]             │ 끊긴 문단 3            │
│                        │ 블록▾ B I ` 링크 ∑ 표 차트 그림 │  …순 | 탄하지  [잇기]  │
│                        │ ─────────────────────────────── │  …삶의 | 의미를 [잇기] │
│                        │ ## 1장 시작                    │ [이 장 모두 적용]      │
│                        │ 본문 문단 …│                    │                        │
│                        │ ┌ $$ ─────────────┐            │ 찾아 바꾸기            │
│                        │ │ P(c|x)=…  │ 미리보기 │       │                        │
│                        │ └─────────────────┘            │                        │
└────────────────────────┴─────────────────────────────────┴────────────────────────┘
```

- 블록 왼쪽에 손잡이(⋮⋮): 누르면 블록 메뉴(종류 바꾸기, 위/아래로, 합치기, 지우기), 끌면 이동
- 저장 상태: "저장됨 / 변경 있음 ● / 저장 중 / 저장 실패". `Ctrl+S` 저장
- 편집기 글자 크기는 리더의 읽기 영역 크기(가−/가+)를 따른다. 메뉴는 12pt 고정

### 7.2 모바일·좁은 화면

720px 이하에서는 편집을 막지 않되 툴바를 한 줄 아이콘으로 줄이고 오른쪽 패널은 서랍으로 둔다. 표·차트 편집기는 넓은 화면을 권한다.

### 7.3 주석과 함께 쓰기

- 저장 후 모든 주석 위치를 다시 찾는다(SPEC §5.1 재탐색). 인용한 글자를 직접 고친 주석은 위치를 잃을 수 있다
- 저장 직후 "주석 n개 중 m개 위치 확인, k개 찾지 못함"을 알리고, 못 찾은 주석은 패널 끝에 모은다
- 편집 중 주석이 걸린 문단을 고치려 하면 문단 옆에 표식을 보여 준다

## 11. 완료 기준

1. **원문 보존**: 아무것도 고치지 않고 저장하면 파일이 바이트 단위로 같다. 한 문단만 고치면 diff에 그 문단 줄만 나온다
2. **렌더링**: 머신러닝 입문의 수식 블록 134개, 마스터링 트랜스포머의 HTML 표 30개가 모두 렌더링된다. 실패한 것은 원문으로 보이고 목록으로 확인할 수 있다
3. **한글 입력**: 한글 조합 중 커서 이동·글자 깨짐 없음. 조합 중 `Enter`가 문단을 나누지 않음
4. **표 왕복**: 파이프 표의 행·열 편집 후 GFM 표로 유효하고, `\|`가 든 셀이 깨지지 않음
5. **안전**: 첫 저장에 `.original.md`가 생기고, 기록에서 어떤 판으로든 되돌릴 수 있음. 외부에서 바뀐 파일은 묻지 않고 덮지 않음
6. **주석**: 저장 후 주석 재탐색 결과를 알리고, 고치지 않은 문단의 주석은 모두 제자리
7. **성능**: 300KB 책에서 편집 모드 진입 1초 이내, 입력 지연 없음
8. **오프라인**: 인터넷 없이 읽기·편집·저장 (AI 문답 제외)

## 13. PoC A 결과 (2026-11-25, Vditor 4.0.1 즉시 렌더링)

### 13.1 원문 보존 측정

실제 책 세 권(머신러닝 입문, 마스터링 트랜스포머, 비트겐슈타인; 42개 장, 20,802줄)을 장마다 Vditor IR에 넣고 아무것도 고치지 않은 채 `getValue()`로 꺼냈다.

| 결과 | 값 |
| --- | --- |
| 원문과 완전히 같은 장 | 42개 중 8개 |
| 바뀐 줄 | 2,008줄 (전체의 9.7%) |
| 바뀐 종류 | 빈 줄 정리 720곳, 파이프 표 칸 맞춤 81곳, 표 구분선 길이, 번호 목록 `01.`→`1.` 5곳 |
| 바뀌지 않은 것 | 별행 수식(`$$`, `aligned`), 인라인 수식, HTML 표(병합 셀 포함), 코드 블록 |
| 장 하나 띄우는 시간 | 중앙값 0.32초, 최대 1.6초 |

결론: Vditor 출력을 그대로 저장하면 안 된다(기준 R2 불충족). `01.`→`1.`은 글 내용이 바뀌는 것이라 특히 막아야 한다.

### 13.2 블록 단위 저장 (`editor.js` `preserveSource`)

저장할 때 편집 직전 Vditor 출력(기준판)과 지금 출력을 줄 단위로 비교한다. 코드 펜스와 `$$` 블록은 통째로 한 단위다. 바뀌지 않은 줄은 원문의 줄과 그 사이 빈 줄을 그대로 쓰고, 바뀌었거나 새로 생긴 줄만 Vditor 출력을 쓴다. 원문과 기준판의 짝은 공백·표 구분선 길이·목록 번호 앞 0을 무시한 키로 맞춘다.

| 시험 (42개 장) | 통과 |
| --- | --- |
| 아무것도 안 고침 → 원문과 바이트 단위로 같음 | 42 / 42 |
| 문단 하나 고침 → 그 줄만 바뀜 | 33 / 33 |
| 문단 삭제 / 새 문단 삽입 / 두 문단 합치기 | 31 / 31, 31 / 31, 31 / 31 |
| 표 칸 하나 고침 → 그 행만 바뀜 | 18 / 18 |

처음 블록(빈 줄 단위)으로 맞췄을 때는 33개 중 5개만 통과했다. 원문의 띄운 목록(`- a`, 빈 줄, `- b`)을 Vditor가 붙여 써서 블록 경계가 달라졌기 때문이다. 줄 단위로 바꾼 뒤 모두 통과했다. 같은 규칙을 저장소 안에서 돌리는 테스트: `node reader/tests/editor_merge.test.js`.

### 13.3 리더에서 처음부터 끝까지 (헤드리스 Chrome, `file://`)

머신러닝 입문 4장(원문 3,388줄)에서 확인했다.

- `E`로 편집 모드 진입, 수식 271개가 KaTeX로 렌더링(별행 `aligned` 포함), 표 안 인라인 수식도 렌더링
- 문단 끝에 영문 입력 후 한글을 IME 조합(ㅎ→하→한→한ㄱ→한그→한글)으로 입력: 한 번만 들어가고 중복 없음
- 편집기 안의 →키가 장을 넘기지 않음, `H`/`M`/`A` 주석 단축키도 작동하지 않음
- `Ctrl+S` 저장: 파일 줄 수 그대로, 본문에서 바뀐 줄은 고친 문단 1줄뿐, front matter에 `edited: true`와 `edited_at`
- `{책}.original.md`(첫 저장 때 한 번)와 `.reader/history/{책}.{시각}.md`(직전 판) 생성
- 편집을 끝내면 읽기 화면이 고친 내용을 보여 주고, 주석은 위치를 다시 찾음
- 마스터링 트랜스포머의 HTML 표는 편집기 안에서 표로 렌더링됨
