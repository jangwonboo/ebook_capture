# Markdown Reader — Kindle Scribe Colorsoft 펜 주석 기획

기준일 2026-11-28. 상태: **기획**. 구현 전에 기기 확인(§3 PoC 0)이 먼저다. 리더 전체 스펙은 [SPEC.md](SPEC.md), 편집 모드는 [EDITOR.md](EDITOR.md).

리더와 책(`{title}.md` + `assets/`)을 Vercel에 올리고, Kindle Scribe Colorsoft의 브라우저에서 열어 펜으로 형광펜을 칠하고 메모를 단다. 주석은 PC 리더와 같은 형식이라 PC에서 이어서 보고, AI 문답도 붙인다.

---

## 1. 목표와 비목표

목표:

- Kindle 브라우저에서 책을 장 단위로 읽는다. e-ink에 맞게 넘기는 화면, 깜빡임 적은 UI
- 펜으로 문장 위를 그으면 그 문장이 칠해진다(색 5개)
- 펜 손글씨 메모: 문장에 붙는 손글씨 메모를 쓰고, 필요하면 글자로 바꾼다
- 주석은 서버에 저장되고 PC 리더와 양방향으로 맞춰진다(같은 주석 형식)
- AI 문답은 서버 함수가 대신 호출한다. Kindle에 API 키를 넣지 않는다

비목표:

- Kindle 기본 독서 앱 수준의 펜 반응 속도 (브라우저 한계, §2)
- 편집 모드(Vditor)를 Kindle에서 쓰기. 편집은 PC에서만
- 여러 사람이 쓰는 공유 서재

## 3. PoC 0 — 기기 탐침 (1일)

`reader/probe.html` 한 장을 Vercel에 올려 Kindle에서 연다. 화면에 결과를 크게 찍고, 같은 내용을 `/api/probe`로 보내 PC에서 본다.

| 확인 | 방법 | 통과 기준 |
| --- | --- | --- |
| 엔진 | `navigator.userAgent`, 문법 검사(`?.`, `??`, `async`, 클래스 필드, ES 모듈) | 결과 기록. 못 쓰면 esbuild로 ES2017까지 낮춤 |
| 펜 이벤트 | `pointerdown/move/up`의 `pointerType`, `pressure`, `buttons`, 초당 `pointermove` 수, `getCoalescedEvents` 유무. `touchstart`·`mousedown`도 같이 기록 | 펜이 손가락과 구분되면 최상. 구분 안 돼도 이벤트가 오면 진행 |
| 펜 옆 버튼 | 누른 채 그을 때 `buttons`/`button` 값 | 형광펜·지우개 전환에 쓸 수 있는지 |
| 스크롤 억제 | `touch-action: none` 영역에서 펜으로 그을 때 페이지가 움직이는지 | 안 움직여야 함 |
| 그리기 지연 | 캔버스에 선을 그려 펜 끝과 선 사이 지연을 눈으로 확인, 고속 촬영 | 150ms 안팎이면 쓸 만함 |
| 글자 위치 찾기 | `document.caretRangeFromPoint`/`caretPositionFromPoint` | 펜 좌표 → 글자 위치가 돼야 형광펜 가능 |
| 저장소 | `localStorage`, `indexedDB`, `fetch`, 쿠키 | 오프라인 대기열에 필요 |
| 화면 | `innerWidth/Height`, `devicePixelRatio`, `matchMedia('(color-gamut: srgb)')`, `(update: slow)` | 레이아웃 기준값 |
| 메모리 | 217KB 책(머신러닝 입문) 파싱·한 장 렌더링 후 멈춤 여부 | 멈추면 장 단위 사전 분할(§6.2) |

PoC 0 결과로 갈림길을 정한다.

| 결과 | 다음 |
| --- | --- |
| 펜이 pointer 이벤트로 오고 스크롤을 막을 수 있음 | 대안 A(웹) 전체 진행 |
| 펜이 터치로만 옴 | 대안 A, 단 "펜 모드" 버튼을 켰을 때만 그리기(손가락·펜 구분 없음) |
| 그리기 이벤트가 안 오거나 지연이 너무 큼 | 형광펜은 길게 눌러 선택 → 색 버튼(지금 PC 방식)으로, 손글씨 메모는 포기하고 키보드 메모. 펜 손글씨가 꼭 필요하면 대안 B |

## 4. 전체 구조 (대안 A: 웹)

```
PC (ebook_capture)                       Vercel                              Kindle Scribe Colorsoft
─────────────────────                    ─────────────────────               ─────────────────────────
D:\ebook\…\{title}.md + assets\   ──▶   정적: reader/ (index.html…)     ◀──   브라우저 → https://…/
   │  deploy 스크립트(빌드·업로드)          책: /books/{id}/…(보호됨)              e-ink 모드 리더
   │                                     함수: /api/notes/{id}  GET/PUT  ◀──▶  펜 형광펜·손글씨 메모
PC 리더(file://) ◀── 주석 동기화 ──▶      함수: /api/ask (Anthropic)     ◀──   AI 문답 요청
                                         함수: /api/ink-to-text
                                         저장소: 주석 JSON, 손글씨 획
```

- 리더는 지금 코드 그대로 정적 파일로 올린다. Kindle에서 열리면 e-ink 모드(§5)가 켜진다
- 주석의 원본 저장소가 둘(PC 폴더의 `{title}.notes.json`, 서버)이 된다. 지금도 쓰는 "주석 단위로 합치고 최신을 남김" 규칙을 그대로 쓴다(§7)

### 4.1 접근 보호 — 필수

올리는 책은 구매한 전자책을 캡처한 것이다. 공개 URL로 두면 배포가 된다. 반드시 막는다.

- 미들웨어에서 전체 경로(`/`, `/books/*`, `/api/*`)를 막고, 개인 비밀문구로 로그인하면 서명된 쿠키(90일)를 준다. Kindle 브라우저에서도 되는 단순한 폼 로그인
- `robots.txt` 전체 차단, `X-Robots-Tag: noindex`
- 책 파일은 정적 공개 경로가 아니라 함수나 미들웨어를 거쳐서만 나가게 한다
- Vercel 자체 보호 기능(Deployment Protection, 비밀번호 보호)은 요금제마다 범위가 다르다. 쓸 수 있으면 함께 켠다. **요금제별 범위는 구현 때 확인**

### 4.2 저장소

| 데이터 | 크기 | 저장 | 비고 |
| --- | --- | --- | --- |
| 책 `.md` + 그림 | 책당 수 MB | 배포에 포함(보호 경로) 또는 Vercel Blob | 책이 자주 바뀌지 않으면 배포 포함이 단순함 |
| 주석 JSON | 책당 수십 KB | Vercel Blob 파일 하나(`notes/{id}.json`) 또는 Redis(Upstash, Marketplace) | 한 사람이 쓰므로 파일 하나 + 버전(ETag) 비교로 충분 |
| 손글씨 획 | 메모 하나에 수 KB | 주석 JSON 안 (`ink` 필드, §6.3) | 이미지가 아니라 벡터라 작다 |

권장은 책은 배포에 포함, 주석은 Blob 파일. 둘 다 Vercel 프로젝트 하나로 끝난다. Blob을 비공개로 둘 수 있는지는 **구현 때 확인**하고, 안 되면 주석은 함수만 읽고 쓰게 한다.

## 6. 펜 기능

### 6.1 형광펜 긋기

1. 펜 모드에서 본문 위를 긋는다. 획을 그리는 동안 캔버스에 반투명 선을 바로 그린다(지연을 줄이려 선만 그림)
2. 펜을 떼면 획의 시작점과 끝점을 `caretRangeFromPoint`로 글자 위치로 바꾸고, 획이 지나간 줄들을 포함하도록 범위를 정한다
3. 범위를 낱말 경계로 넓히고(한국어는 어절 단위), 지금 주석 형식(장 ID, 블록 번호, 인용, 앞뒤 20자)으로 만든다. 같은 범위가 있으면 색만 바꾼다(지금 규칙)
4. 캔버스의 임시 선을 지우고 `<mark>`로 다시 그린다

판정 규칙:

| 획 모양 | 해석 |
| --- | --- |
| 거의 수평, 줄 높이 안 | 그 줄의 해당 구간 칠하기 |
| 여러 줄을 지그재그·대각선으로 | 첫 점부터 끝 점까지 연속 범위 |
| 칠한 곳 위를 지우개로 | 그 주석의 색 지움(메모가 있으면 확인 후) |
| 짧은 점(5px 미만) | 탭으로 보고 무시. 칠한 곳이면 주석 메뉴 |

손가락은 펜 모드에서도 넘기기와 메뉴만 한다(펜과 구분되는 경우).

### 6.2 성능

- 책 전체 대신 장 단위로 불러온다. 배포 스크립트가 장별 HTML 조각과 목차 JSON을 미리 만든다(Kindle에서 Markdown 파싱 생략). PC 리더는 지금처럼 `.md`를 읽는다
- 장 안의 그림은 보이는 쪽에서만 불러오고, 배포 때 긴 변 1600px·흑백 친화 JPEG로 줄인 판을 따로 둔다
- 수식(KaTeX)은 배포 때 HTML로 미리 렌더링해 Kindle에서 계산하지 않는다

### 6.3 손글씨 메모

- 칠한 곳을 펜으로 탭 → 주석 메뉴 → "손글씨". 화면 아래 절반에 쓰기 칸(줄 노트 모양)이 열린다
- 획은 `{t, c, w, pts: [[x, y, p], …]}`(시간, 색, 굵기, 좌표·필압) 배열로 저장한다. 좌표는 쓰기 칸 기준 0–1000 정수로 줄이고, 획마다 점을 단순화(Douglas–Peucker, 허용 오차 1.5)해 메모 하나에 수 KB로 둔다
- 표시는 SVG `<path>`로. PC 리더 주석 카드에서도 같은 SVG로 보인다
- "글자로 바꾸기": 획을 PNG로 그려 `/api/ink-to-text`로 보내면 서버가 Claude 비전으로 읽어 텍스트를 돌려준다. 결과는 기존 `memo` 필드에 넣고, 손글씨는 그대로 둔다(둘 다 보관)
- 본문 여백 손글씨(문장에 붙지 않는 메모)는 2단계. 장 + 블록 번호에 붙는 "여백 메모" 주석으로 저장

### 6.4 키보드 메모와 AI 문답

- Kindle 화면 키보드로 메모 쓰기는 지금 카드 그대로
- AI 문답은 `/api/ask`가 받는다. 서버가 장 본문·인용·이전 문답을 붙여 Anthropic API를 부르고(키는 Vercel 환경 변수), 결과를 그대로 주석에 넣는다. 스트리밍 대신 완성된 답을 한 번에 보낸다(e-ink 깜빡임 줄임)
- PC 리더도 서버를 쓸 수 있으면 `/api/ask`를 쓰게 설정 하나로 바꾼다. 지금처럼 브라우저에서 키로 직접 부르는 방식은 남긴다

## 7. 주석 동기화

주석 형식은 지금 것(`{title}.notes.json`)에 필드만 더한다.

```ts
interface Annotation {
  // 지금 필드: id, node, block, quote, prefix, suffix, color, memo, tags, turns, created/updated, lost …
  ink?: InkMemo;                    // 손글씨 메모 (§6.3)
  source?: 'pc' | 'kindle';         // 마지막으로 고친 기기
  deleted?: string;                 // 지운 시각 (지운 것도 맞추려면 묘비가 필요)
}
interface InkMemo { w: number; h: number; strokes: { t: number; c: string; w: number; pts: number[][] }[]; text?: string }
```

| 쪽 | 동작 |
| --- | --- |
| Kindle | 열 때 `GET /api/notes/{id}` → 바꿀 때마다 `PUT`(본문에 마지막으로 받은 버전). 실패하면 `localStorage` 대기열에 두고 다음 성공 때 보냄 |
| 서버 | 버전이 다르면 거부하지 않고 주석 단위로 합침: `updated`가 늦은 쪽, 지운 것은 `deleted`가 더 늦으면 지움 |
| PC 리더 | 설정에 "서버 동기화"(주소 + 비밀문구). 켜면 책을 열 때와 저장할 때 서버와 합치고, 결과를 폴더의 `{title}.notes.json`에도 씀 |
| 파이프라인 | 책이 다시 만들어지면 지금처럼 리더가 위치를 다시 찾음. 서버 쪽 주석도 같은 규칙 |

책 ID는 지금 리더 규칙(제목 기반)을 쓰되, 같은 제목의 판이 다를 수 있으므로 배포 스크립트가 `{id}` = 제목 slug + 본문 해시 앞 8자로 고정한다. PC 리더는 front matter의 `reader_id`로 같은 ID를 읽는다.

## 8. 배포 스크립트

`python -m ebook_capture.reader_deploy D:\ebook\…\{title}.md`(이름 가안):

1. 책 폴더 읽기 → `{id}` 정함
2. 장별 HTML 조각, 목차 JSON, 수식 미리 렌더링, 그림 축소판
3. `reader/` 정적 파일과 함께 `dist/`에 모음
4. `vercel deploy --prod`(Vercel CLI). 책 목록 페이지(`/`)에 추가

캡처 파이프라인 범위와는 떨어뜨린다. 배포 코드는 `reader/deploy/`에 두고 파이프라인 모듈을 건드리지 않는다.

## 9. 대안 B: Kindle 기본 독서 앱 + 주석 되가져오기

PoC 0에서 펜이 웹에서 안 되면 쓴다. 펜 반응 속도와 손글씨는 이쪽이 가장 좋다.

1. 리더의 **EPUB** 버튼으로 내보내기(목차·Pretendard·수식 SVG 포함, [SPEC.md](SPEC.md) "EPUB 내보내기") → Send to Kindle
2. Kindle 기본 앱에서 펜으로 형광펜(5색)·밑줄·Active Canvas 손글씨·메모
3. 기기에서 "공유"로 주석을 메일로 받음(2025년 이후 Scribe). 받은 파일에서 형광펜 인용과 메모를 뽑아 `{title}.notes.json`에 합침. 인용 → 위치는 지금 리더의 위치 재탐색으로 찾음

한계:

- 내보낸 파일 형식과 형광펜 색·위치가 얼마나 남는지 **확인 불가**. 형광펜은 원래 파일 안에 남는다는 설명이라 인용을 뽑으려면 내보낸 PDF를 분석해야 할 수 있다
- Active Canvas 손글씨는 그림으로만 온다. 글자로 바꾸려면 §6.3처럼 Claude 비전을 거쳐야 한다
- 매번 손으로 내보내고 가져와야 한다(자동 동기화 없음)
