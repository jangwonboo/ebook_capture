# Markdown Reader — 웹 리더 기획·스펙

기준일 2026-11-25. 사용법은 [README.md](README.md), 제품·디자인 요약은 [PRODUCT.md](PRODUCT.md)와 [DESIGN.md](DESIGN.md). 이 문서는 무엇을 왜 이렇게 만들었는지, 무엇이 남았는지를 다룬다. 기능마다 구현 여부를 표시했다.

---

## 1. 제품 정의

캡처 파이프라인이 만든 Markdown(스캔 책을 OCR한 것)을 브라우저에서 편하게 읽고, 찾고, 표시하고, 이해하도록 돕는 개인용 리더. 원본 PDF의 정체성(표지, 박스, 그림)은 살리고, 읽기는 다시 흐르는(reflow) 본문으로 한다.

목표:

- 긴 본문을 데스크톱과 모바일에서 편하게 읽는다
- 목차, 검색, 저장한 위치로 원하는 곳에 바로 간다
- 읽으며 칠하고, 메모하고, 모르는 대목을 AI에게 물어 주석으로 남긴다
- OCR이 끊어 놓은 글(쪽 경계, 두 줄 제목)은 이어서 보여 준다

비목표:

- PDF를 이미지 뷰어로 다시 만드는 일
- AI가 원문을 요약·재서술해 원문 자리를 대신하는 일
- 계정·동기화·공동 주석 같은 서버가 필요한 기능
- 리더에서 OCR 오탈자를 고쳐 쓰는 일(파이프라인에서 한다, §8)

## 2. 원칙

- 책이 화면의 주인공이다. 도구는 필요할 때만 보인다
- 원문과 주석을 섞지 않는다. 주석은 원문 옆 패널이나 원문 위 표시(색, 밑줄, 표식)로만 보인다
- 사람이 쓴 것과 AI가 쓴 것은 화면과 내보낸 파일 어디에서도 구분된다. AI 답은 근거 원문으로 돌아갈 수 있어야 한다
- 로컬이 기본이다. 서버가 없고, 책 내용이 밖으로 나가는 것은 AI 문답을 켜고 책마다 동의한 뒤뿐이다
- 주석은 책 폴더의 파일로 남는다. 브라우저 데이터를 지워도, 폴더를 옮겨도 따라온다
- AI 없이도 나머지 기능은 그대로 동작한다

## 3. 화면 구성

```text
┌ 상단: ☰ Markdown Reader · 책 제목 ··· 폴더 열기 · 파일 열기 · 글꼴 · 가−/가+ · ◐ · ⚙ ┐
├ 목차/검색/저장 ┬─────────── 본문 ───────────┬──── 주석 (선택) ───┤
│ ▾ Part 1       │ Part 1 › 1장 › 소제목   ☆ 주석 │ 범위·색·종류·태그    │
│   ▾ 1장        │ ─────────── 진행 막대 ────────── │ 주석 카드            │
│     소제목 가  │  1장 제목                      │  "인용"  메모 #태그  │
│     소제목 나  │  본문 … ████칠한 문장████ ✎    │  Q / AI 답 / 근거    │
│   ▸ 2장        │  ← 이전 장        다음 장 →    │ 내보내기·가져오기    │
└────────────────┴────────────────────────────────┴──────────────────────┘
```

- 시작 화면: "우상단 버튼으로 폴더나 파일을 열어주세요" 한 줄만 둔다
- 왼쪽 사이드바: 목차 / 검색 / 저장 탭. 경계선을 끌어 너비 조절, ☰로 접기
- 가운데: 장 하나가 한 화면. 소제목은 본문 안 제목으로 두고, 스크롤하면 트리의 현재 항목이 따라 바뀐다
- 오른쪽 주석 패널: "주석" 버튼으로 연다. 1050px 이하에서는 본문 위에 겹친다
- 720px 이하에서는 왼쪽 사이드바가 서랍이 된다

## 4. 기능

### 4.1 열기 — 구현

| 방법 | 동작 |
| --- | --- |
| 폴더 열기 | Chrome·Edge는 쓰기 권한으로 연다(주석 파일 저장 가능). 하위 4단계까지 Markdown과 이미지를 모은다. Markdown이 여럿이면 고르는 창 |
| 파일 열기 | Markdown(필요하면 이미지 함께)만 선택. 읽기 전용 |
| 끌어다 놓기 | 파일이나 폴더. 읽기 전용 |

이미지 링크(`![그림](assets/…)`)는 Markdown 위치 기준 상대 경로로 따라가고, 못 찾으면 파일 이름으로 찾는다. 브라우저는 고른 파일 옆 폴더를 읽을 수 없어서, 그림까지 보려면 폴더째 열어야 한다.

### 4.2 Markdown 해석 — 구현

- 맨 앞의 front matter(`---` … `---`)만 버린다. 본문 중간의 `---`는 구분선
- 맨 앞의 본문 없는 `#` 제목은 책 제목으로 쓰고 트리에서 뺀다(뒤에 `#`가 하나도 없거나 바로 다음이 `#`일 때)
- `##` 이하가 한 화면(장). 더 깊은 제목은 그 화면 안 제목. 기준은 `app.js`의 `PAGE_LEVEL`
- 본문 없이 하위 장만 있는 제목(Part)은 트리에 남고, 누르면 첫 하위 장으로 간다
- `#### INSIGHT` 뒤 블록은 카드로 묶는다(다음 제목까지)
- 문단, 인용, 목록(번호/글머리), 표, 코드 펜스, 이미지를 각각 렌더링
- `<!-- pages: a-b -->` 주석이 있으면 장 제목 아래 "원문 p.a–b"

### 4.3 끊긴 글 복원 — 구현

파이프라인(`core/seam_repair.py`)과 같은 규칙을 리더에도 둔다. 이미 만든 Markdown도 다시 만들지 않고 바로 읽히게 하려는 보조 장치이고, Markdown 파일은 바꾸지 않는다.

- 같은 수준의 소제목이 본문 없이 연달아 나오면 한 제목으로 잇는다(문장부호로 끝나거나 번호로 시작하면 제외)
- 소제목 바로 앞의 짧은 구절("마흔,", "삶에서")은 제목 첫 줄로 붙인다
- 40자 이상인데 문장부호 없이 끝난 문단은 다음 문단과 잇는다. 띄어쓰기는 책 전체 낱말 목록으로 판단한다

규칙 자체는 [ARCHITECTURE §8.3](../docs/ARCHITECTURE.md#83-문단-정리-full--prose).

### 4.4 탐색 — 구현

- 목차 트리: 화살표는 펼침/접힘만, 제목은 이동. 필터, 모두 펼치기/접기. 끝까지 읽은 장에 ●, 상위 항목에 읽은 장 수
- 경로 표시(Part › 장 › 소제목)의 각 단계로 이동
- 이전/다음 장 버튼에 장 제목 표시
- 주소에 위치 반영(`#/제목-id`): 새로고침해도 같은 자리
- 검색: 제목과 본문, 결과 50개까지, 누르면 그 문단으로 가서 강조
- 저장한 위치: 별표로 저장·해제, 저장 탭에서 이동

### 4.5 읽기 설정 — 구현

본문 글꼴 4종(기본 명조, Pretendard, KoPub 바탕, KoPub 고딕; 설치된 글꼴 우선), 테마 3종(밝게, 어둡게, 고대비). 이 값들은 브라우저에만 저장한다.

글자 크기는 두 층으로 나눈다.

| 층 | 대상 | 크기 | 글꼴 |
| --- | --- | --- | --- |
| 본문 | 읽기 화면과 편집기의 본문 | 기본 14pt, 가−/가+로 9–24pt (1pt씩) | 선택한 글꼴 |
| 주석 카드 | 인용·메모·문답·버튼 | 14pt 고정 | Pretendard 고정 |
| 그 밖의 모든 것 | 목차·검색·저장 패널, 주석 패널 머리·필터, 상단 바, 탭, 버튼, 경로 표시, 선택 도구, 대화상자 | 12pt 고정 | Pretendard 고정 |

본문 안의 보조 글자(쪽 표시, 캡션)는 본문 크기에 대한 비율(0.75em)이라 함께 움직인다. 패널의 보조 글자(메타, 태그)는 12pt에 대한 비율로 고정이다.

문단 폭은 본문 영역(스크롤 영역 안쪽) 대비 비율이다. 기본 70%, 10%씩 바뀐다. 범위는 한 줄 글자 수로 정한다: 한글은 글자당 약 1em이라 줄 너비가 20em 이상, 50em 이하가 되는 10% 단위 값만 허용하고(바깥 한계 30–100%), 본문 영역 너비나 글자 크기가 바뀔 때마다(패널 여닫기·끌기, 창 크기, 가−/가+) 다시 계산한다. 고른 값은 저장해 두고, 지금 범위를 벗어나면 화면에만 범위 안 값을 쓴다. 편집기 본문도 같은 폭을 따른다.

패널 너비는 경계선 가운데 손잡이로 조절한다. 목차 200–560px(기본 290), 주석 280–680px(기본 360), 본문 영역은 최소 360px. 누른 자리에서 끈 거리만큼 바뀌고, 두 번 누르면 기본값, 키보드는 ←/→ 16px. 값은 브라우저에 저장한다.

패널 여닫기 버튼은 둥근 사각형 테두리에 한쪽 칸이 찬 아이콘이다. 왼쪽 패널은 왼쪽이, 주석 패널은 오른쪽이 차 있고, 각각 상단 바의 왼쪽 끝과 오른쪽 끝에 있다. 20×20 격자의 SVG라 화면 배율과 관계없이 선명하다.

### 4.6 주석 — 구현

- 문장을 드래그하면 선택 도구: 색 4개, 메모, AI, 복사. 칠한 곳을 누르면 색 변경, 메모, AI에게 묻기, 삭제
- 같은 구간을 다시 고르면 새로 만들지 않고 색만 바꾼다. 여러 문단에 걸친 선택도 한 주석
- 메모는 카드 안에서 바로 쓰고, `#낱말`은 태그가 된다
- 본문 표식: 메모 ✎, AI 문답 ✦. AI만 있는 주석은 색 없이 밑줄
- 주석 카드의 글자는 모두 14pt Pretendard(인용 포함). 원문 위치 줄은 위치를 잃었을 때만 "원문에서 위치를 찾지 못함"으로 보인다. 문답의 Q·AI 꼬리표는 첫 줄과 같은 기준선에 맞춘다
- 패널: 범위(전체 / 이 장), 색, 종류(메모 있음 / AI 문답 있음), 태그로 거르고, 인용·메모·AI 답에서 검색. 인용을 누르면 본문 그 자리로

### 4.7 저장 — 구현

| 책을 연 방법 | 주석 저장 |
| --- | --- |
| 폴더 열기 (Chrome·Edge) | 책 폴더 `<책>.notes.json`에 자동 저장 |
| 파일 열기, 끌어다 놓기 | 브라우저에만. 패널의 "브라우저에만 저장됨"을 누르고 책 폴더를 고르면 파일 저장으로 바뀜 |
| Firefox·Safari | 브라우저에만. "JSON 내보내기"로 내려받음 |

- 변경 0.8초 뒤 저장. 패널 머리에 "파일에 저장됨 / 저장 중… / 브라우저에만 저장됨 / 파일 저장 실패"
- 브라우저 저장소에도 항상 사본을 둔다. 열 때 파일과 사본을 주석 단위로 합치고 최신을 남긴다. 파일이 더 최신이면 읽던 위치·읽음·저장한 위치도 파일 것을 쓴다
- Markdown 내보내기(장별 인용·메모·채택한 AI 답), JSON 내보내기·가져오기
- 책이 다시 만들어져 내용이 바뀌면 모든 주석 위치를 다시 찾고 결과를 알린다

### 4.8 AI 문답 — 구현

1. 문장을 고르고 선택 도구의 "AI"(단축키 `A`), 또는 카드의 "AI에게 묻기"
2. 질문을 쓰거나 미리 준비된 질문(쉽게 풀어 줘 / 앞뒤 맥락 / 용어·인물 / 반론; 설정에서 편집)을 고른다
3. 답이 흘러나오고, 끝나면 근거 문장 버튼이 달린다. 누르면 본문 그 문단으로 가서 강조
4. 이어 물으면 그 주석의 문답에 쌓인다
5. "주석으로 채택"하면 대표 답이 되어 내보내기에 들어간다. "메모로 복사"로 고쳐 쓸 수 있다

AI에게 넘기는 것: 답변 규칙·책 제목·목차(시스템 프롬프트), 지금 장의 본문 전체(인용을 켠 문서 블록), 고른 원문, 이 주석의 이전 문답, 새 질문. 메모와 다른 주석은 보내지 않는다. 답변 규칙: 근거가 있으면 인용, 문서 밖 지식은 "책 밖의 설명:"으로 시작, 원문을 길게 옮기지 않고 서너 문단의 평문, OCR 오탈자를 감안하되 불확실하면 말한다.

표시: "AI" 꼬리표와 답. 모델 이름, 날짜, 토큰 사용량은 주석 파일에만 저장하고 카드에는 보이지 않는다(Markdown 내보내기에는 모델·날짜가 들어감). 근거가 없으면 "근거 문장 없음 (책 밖의 설명일 수 있음)".

동의: 책마다 처음 물을 때 전송 범위와 과금을 안내하고 동의를 받는다.

실패하면 질문은 입력란에 남고 문답에 저장하지 않는다.

| 상황 | 화면 |
| --- | --- |
| 키 없음, 키 틀림(401) | 설정 창을 열고 안내 |
| 모델 권한 없음(403), 모델 없음(404) | 원인 안내 |
| 사용량 제한(429) | 다시 보낼 수 있는 시간 안내 |
| 연결 실패, SDK를 못 불러옴 | 인터넷 연결 확인 안내 |
| 모델이 답을 거절함 | "모델이 이 질문에는 답하지 않았습니다" |
| "중지" | 조용히 취소 |

### 4.9 설정 — 구현

| 항목 | 내용 |
| --- | --- |
| Anthropic API 키 | "이 브라우저에 키 저장"을 켜면 브라우저 저장소에, 끄면 창을 닫을 때까지 메모리에만. "저장된 키 지우기" |
| 모델 | Claude Sonnet 5.5(기본), Claude Opus 5.5, Claude Haiku 5.5 |
| 미리 준비된 질문 | 한 줄에 하나, `버튼 이름 \| 보낼 질문` |

키는 주석 파일과 내보낸 파일에 들어가지 않는다. 다만 브라우저에 저장하면 같은 PC의 다른 로컬 HTML 파일이 읽을 수 있다(더블클릭으로 연 페이지들은 저장소를 같이 쓴다). 설정 창에 적어 두었다.

## 5. 데이터

### 5.1 주석

```ts
type Annotation = {
  id: string;
  anchor: Anchor[];            // 여러 문단에 걸치면 문단별로
  quote: string;
  color: 'yellow' | 'green' | 'blue' | 'pink' | null;  // null이면 밑줄만
  note: string;
  tags: string[];              // note의 #낱말
  thread: Turn[];              // AI 문답
  pinned?: number;             // 채택한 답의 번호
  lost?: boolean;              // 원문에서 위치를 찾지 못함
  createdAt: number; updatedAt: number;
};
type Anchor = { node: string; block: number; start: number; end: number; text: string; before: string; after: string };
type Turn = {
  role: 'user' | 'assistant'; text: string; at: number;
  citations?: { quote: string; node: string; block: number }[];
  model?: string; usage?: { input: number; cached: number; output: number };
};
```

`node`는 제목 ID, `block`은 그 제목 아래 몇 번째 블록. 위치 재탐색 순서: 저장된 위치 그대로 → 같은 제목 아래에서 원문 검색 → 같은 장에서 앞뒤 20자 포함 검색, 다음으로 원문만 → 책 전체에서 같은 순서 → 실패하면 `lost`. 이전 버전이 브라우저에 남긴 하이라이트는 처음 열 때 이 형식으로 옮긴다.

### 5.2 주석 파일 `<책>.notes.json`

```json
{
  "version": 1,
  "book": { "title": "…", "file": "책.md", "contentHash": "…" },
  "position": "제목-id",
  "read": ["…"],
  "saved": [{ "id": "…", "createdAt": 0 }],
  "annotations": [],
  "deleted": { "주석-id": 0 },
  "updatedAt": 0
}
```

`deleted`는 지운 주석이 다른 사본에서 되살아나지 않게 하는 기록이다. 캡처 파이프라인은 이 파일을 만들거나 지우지 않는다.

## 6. 기술 구조

| 파일 | 역할 |
| --- | --- |
| `index.html`, `styles.css` | 화면 |
| `app.js` | 파서(`Yeobaek.parseBook`, Node에서 `require` 가능), 목차, 본문, 검색, 읽기 설정, 열기 |
| `notes.js` | 주석, 주석 파일, 내보내기·가져오기, AI 설정과 문답 |

- 빌드 없이 일반 `<script>`. 더블클릭(`file://`)으로 열린다. 외부에서 받는 것은 글꼴 CSS와(AI를 쓸 때) SDK뿐
- `notes.js`는 `app.js`의 훅(`pageRendered`, `bookOpened`, `changed`, `key`)에 붙는다. `notes.js`가 없어도 리더는 동작한다
- 화면 밖 렌더링: 위치 재탐색과 AI에게 넘길 장 본문은 이미지를 불러오지 않는 별도 문서에 장을 렌더링해 만든다. 화면과 같은 블록 번호 규칙이라 인용 위치와 하이라이트 위치가 맞는다

AI 호출:

- 공식 TypeScript SDK `@anthropic-ai/sdk` 1.12.0을 처음 물을 때 `https://esm.sh/@anthropic-ai/sdk@1.12.0?bundle`에서 불러온다. 여러 파일로 나뉜 빌드는 `file://`에서 20초 넘게 걸려 단일 파일 빌드를 쓴다. 20초 안에 못 불러오면 실패
- `new Anthropic({ apiKey, dangerouslyAllowBrowser: true })`, `client.messages.stream(...)`, `max_tokens` 64000, `output_config.effort` `medium`. thinking 설정은 넣지 않는다(모델 기본값)
- 프롬프트 캐싱: 시스템 프롬프트와 장 문서 블록이 요청마다 같고, 문서 블록에 `cache_control`. 같은 장에서 이어 물으면 본문을 캐시에서 읽는다(기본 5분)
- 인용: 장 본문을 평문 문서 블록(`citations: {enabled: true}`)으로 넣고, 돌아온 `char_location`을 블록 번호로 바꾼다
- `stop_reason`이 `refusal`이면 저장하지 않는다. 서버 측 대체 모델(`fallbacks`)은 켜지 않았다
- 오류는 SDK 예외 클래스(`AuthenticationError`, `RateLimitError`, `APIConnectionError` …)로 구분

참고 단가(100만 토큰당 입력/출력, 2026-11-03 기준): Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, Haiku 5.5 $0.10/$0.50. 실제 사용량은 주석 파일의 각 답(`usage`)에 남는다.

## 8. 파이프라인과의 경계

리더는 파이프라인 산출물(`{title}.md`, `assets/`)을 읽기만 한다. OCR 품질 문제는 파이프라인에서 고친다: 쪽 경계 띄어쓰기와 두 줄 제목은 `seam_repair`, 오탈자는 사전과 `--proofread`(ARCHITECTURE §8). 리더 쪽 복원 규칙(§4.3)은 이미 만든 Markdown을 위한 것이라, 파이프라인으로 다시 조립한 책에서는 할 일이 없다.
