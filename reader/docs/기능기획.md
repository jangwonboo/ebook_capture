# Visual eBook 기능 기획

> 후속 문서: 주석·저장·AI 문답은 `추가기획.md`에서 다룬다.
> 2026-11-25 결정으로 OCR 교정은 캡처 파이프라인에서 하기로 했다. 5-E와 Phase 3의 "교정 제안·편집 검수" 화면은 보류하고, 원문 대조(스캔 페이지 보기)만 남긴다.

## 1. 제품 정의

스캔 PDF의 편집 미감과 Markdown의 검색성을 결합한 개인용 웹 리더. 독자는 책을 처음부터 읽거나, 현재의 문제 상황에 맞는 전략 챕터를 바로 찾아 읽고, 핵심 문장을 저장·적용할 수 있다.

### 목표

- 긴 본문을 모바일과 데스크톱에서 편하게 읽게 한다.
- 원본 PDF의 표지, 장식 페이지, 주요 박스 등 시각적 정체성을 보존한다.
- OCR 오류와 문단 분할을 독자가 원문과 대조해 신뢰할 수 있게 한다.
- "작전 경로"라는 책의 독서 방식을 실제 탐색 경험으로 구현한다.

### 비목표

- PDF를 단순 이미지 뷰어로 다시 만드는 일
- 원문을 AI가 요약·재서술해 대체하는 일
- 계정·공유·결제 등 서버가 필요한 기능을 1차 버전에 넣는 일

## 2. 근거와 기획 방향

| 원본 관찰 | 제품 판단 |
| --- | --- |
| 스캔본 PDF, 텍스트 레이어 없음 | 원문 이미지는 증거·미감용으로 보존하고, 읽기는 정제된 HTML 본문으로 분리 |
| MD에 125개 이미지 | 이미지가 등장한 위치와 캡션을 구조화해 본문과 함께 배치. 단, 스캔본 pdf에서 page 면적 전체에 이미지가 깔려있으면 이 이미지를 그대로 사용하고 추출된 text 병행사용 |
| 목차 구성 | 전진 경로의 최상위 내비게이션으로 사용 |
| 주요 박스 표식                 | 별도 카드, 필터, 저장 단위로 승격 |
| OCR 줄바꿈·오인식 흔적 | 원문 대조와 교정 제안 워크플로를 기본 제공 |

## 3. 독자와 핵심 시나리오

### 전진 독자

1. 표지에서 “처음부터 읽기”를 선택한다.
2. Part → 인물/주제 → 소제목 순으로 읽는다. (책에 따라 구조는 변경가능)
3. 이어 읽기 위치와 전체 진도를 자동으로 복원한다.

### 작전 독자

1. “지금 어떤 판인가?”를 선택한다. 예: 협상에서 밀림, 주도권 확보, 상대 설득, 위기 생존.
2. 관련 Part·챕터·주요 인사이트·요약 부분을 추천받는다.
3. 읽은 내용을 카드로 저장하고 자신의 상황과 다음 행동을 메모한다.

### 대조·교정 독자

1. 이상한 문장이나 누락을 발견한다.
2. “원문 보기”로 대응 스캔 페이지와 문단을 나란히 확인한다.
3. 오탈자 제안을 로컬에 저장하고, 편집 검수 화면에서 승인한다.

## 4. 정보 구조

```text
홈/표지
├─ 이어 읽기
├─ 전진 경로
│  └─ Part 1~4 → 챕터 → 섹션 → 본문/Insight
├─ 작전 경로
│  └─ 상황 태그 → 추천 챕터/Insight
├─ 전체 목차
├─ 검색
├─ 저장함
│  ├─ 하이라이트
│  ├─ Insight
│  └─ 내 메모
└─ 설정·편집 검수
   ├─ 읽기 환경
   └─ OCR 교정 제안
```

## 5. 1차 출시 기능(MVP)

### A. 리더

- 한 화면에 한 읽기 단위(섹션)를 보여 주고, 앞·뒤 섹션으로 넘긴다.
- 상단에는 현재 Part와 챕터, 하단에는 섹션 진도와 남은 읽기 시간을 표시한다.
- 왼쪽 목차 패널은 Part/챕터 단위로 접고 펼친다.
- URL은 `/#/part-1/sun-ja/천-타이밍은-누구의-편인가`처럼 의미 있는 앵커를 쓴다. 새로고침·공유 후에도 같은 위치를 연다.
- 읽던 위치는 `localStorage`에 저장한다. 계정 없이도 마지막 위치를 복원한다.
- 본문 너비, 글자 크기, 줄간격, 고대비, 다크 모드를 제공한다.

### B. 두 가지 경로

- **전진 경로:** Part 1 → Part 4 순서와 각 Part의 목적을 보여 준다.
- **작전 경로:** 책 속 설명을 바탕으로 `판 읽기`, `주도권`, `설득·심리전`, `위기·생존` 4개 진입점으로 제공한다.
- 각 진입점에서 3~6개 챕터를 제시하고, 선택 이유를 한 줄로 쓴다. 추천은 원문 태그 기반으로 시작하며 AI 추천을 전제하지 않는다.

### C. Insight 카드

- `#### INSIGHT`를 자동 인식해 본문에서 시각적으로 분리한다.
- “Insight만 보기” 필터와 Part별 Insight 목록을 제공한다.
- 카드에는 원문 위치, 저장 버튼, 메모 필드를 둔다.
- 카드 클릭 시 본문 문맥으로 이동하고, 되돌아올 수 있다.

### D. 검색·저장

- 제목·본문·인물명·태그를 대상으로 즉시 전문 검색한다.
- 검색 결과에는 Part, 챕터명, 일치 문장 주변 1~2문장을 함께 보여 준다.
- 문장 또는 Insight 단위로 형광펜 4색, 북마크, 개인 메모를 지원한다.
- 저장함은 최신순/색상/Part/태그로 필터링한다.
- 1차 버전 데이터는 브라우저 로컬 저장소에 보관하고 JSON 내보내기·가져오기를 지원한다.

### E. 원문 대조 및 OCR 품질

- 문단·이미지에 `sourcePage`와 `sourceRegion` 메타데이터를 둔다.
- “원문 보기”를 누르면 우측 패널 또는 모달에 해당 PDF 페이지를 표시하고 현재 문단 위치를 강조한다.
- 독자는 `누락`, `오인식`, `문단 분할`, `순서 오류` 중 하나를 골라 교정안을 제출한다.
- 편집 검수 화면에서는 제안, 원문 이미지, 수정 전후를 함께 보고 승인·반려한다.
- 승인된 교정은 콘텐츠 JSON에 반영하고 `contentVersion`을 올린다. 개인 하이라이트는 문단 ID를 기준으로 유지한다.

## 6. 화면별 요구사항

| 화면 | 핵심 구성 | 핵심 행동 |
| --- | --- | --- |
| 홈/표지 | 표지, 마지막 읽기, 두 경로, Part 지도 | 이어 읽기·경로 선택 |
| 리더 | 접이식 목차, 본문, 떠 있는 읽기 도구 | 다음 섹션·글자 조절·저장·원문 대조 |
| 작전 경로 | 상황 선택, 추천 카드, 선택 근거 | 현재 문제에서 챕터 열기 |
| 검색 | 검색창, 결과, 필터 | 문맥 확인 후 해당 문단 이동 |
| 저장함 | 하이라이트·Insight·메모 탭 | 복습·필터·내보내기 |
| 원문 대조 | 스캔, HTML 문단, 교정 폼 | 확인·교정 제안 |
| 편집 검수 | 제안 목록, 원문, 변경 비교 | 승인·반려·버전 발행 |

## 7. 콘텐츠 모델

정규화된 콘텐츠를 HTML이 아닌 JSON으로 관리한다. HTML은 이 데이터로 렌더링한다.

```ts
type Section = {
  id: string;                 // 변경되지 않는 문단/섹션 식별자
  partId: 'part-1' | 'part-2' | 'part-3' | 'part-4';
  chapterId: string;
  title?: string;
  blocks: Block[];
  tags: string[];             // 예: 협상, 타이밍, 억제
  source: { pageStart: number; pageEnd: number; region?: string };
};

type Block =
  | { type: 'paragraph'; id: string; text: string }
  | { type: 'heading'; level: 2 | 3 | 4; text: string }
  | { type: 'image'; asset: string; alt: string; sourcePage?: number }
  | { type: 'insight'; id: string; text: string }
  | { type: 'quote'; text: string; attribution?: string };
```

### 변환 규칙

1. 중복된 Part 표지·Part 제목은 하나의 `Part` 레코드로 합친다.
2. `###`는 챕터/소제목, `#### INSIGHT`는 `insight` 블록으로 변환한다.
3. OCR 줄바꿈은 문장 단위로 병합하되, PDF 대조가 끝나지 않은 문단에는 `reviewStatus: pending`을 둔다.
4. 이미지 파일은 해시 기반 파일명으로 복사하고, alt 텍스트와 출처 페이지를 편집 검수에서 채운다.
5. 변환 실패·모호한 제목은 조용히 추정하지 않고 검수 큐에 넣는다.

## 8. UX·시각 원칙

- Business Magazine과 같은 UI 구성 추구
- Font는 3-4단계로 계층화 (예 12pt, 14pt, 16pt, 20pt등)
- font size 조절 (+,_) 기능 추가
- 표지와 Part 시작 면은 원본 준수. 본문은 장식보다 가독성을 우선한다.
- 본문 최대 폭은 데스크톱 680px 안팎, 모바일은 양쪽 여백 20px 이상으로 둔다.
- 제목은 강한 대비의 명조 계열, 본문은 화면 가독성이 좋은 한글 본문용 서체로 분리한다. 상용 폰트는 라이선스를 확인한다.
- 인사이트/요약 내용은 원본의 녹색 탭과 크림색 박스를 현대적으로 단순화한 카드로 표시한다.
- 모션은 페이지 전환이 아니라 목차 열림·저장 상태 같은 상태 변화에만 짧게 쓴다. `prefers-reduced-motion`을 따른다.
- 키보드로 목차, 검색, 이전/다음 섹션, 글자 크기 조절을 수행할 수 있어야 한다.

## 9. 구현 범위와 단계

### Phase 0: 콘텐츠 정제

- MD 파서와 콘텐츠 JSON 스키마를 만든다.
- Part/챕터/Insight/이미지를 구조화한다.
- PDF 페이지 번호와 콘텐츠 블록을 매핑하는 편집용 인덱스를 만든다.
- 대표 챕터 1개로 OCR 교정 기준을 확정한다.

### Phase 1: 읽기 가능한 리더

- 홈, 전진 경로, 리더, 목차, 읽기 설정, 마지막 위치 복원을 구현한다.
- Part 1 전체로 반응형·접근성·가독성 검증을 끝낸다.

### Phase 2: 탐색과 복습

- 작전 경로, 검색, Insight 필터, 하이라이트·메모·저장함을 구현한다.
- 로컬 데이터 내보내기·가져오기를 제공한다.

### Phase 3: 원문 신뢰성

- PDF 원문 대조 패널과 교정 제안·검수 기능을 구현한다.
- 승인된 교정 반영과 콘텐츠 버전 관리 흐름을 만든다.

## 10. 완료 기준

- 모바일 360px, 태블릿, 데스크톱에서 가로 스크롤 없이 읽힌다.
- 목차·검색·작전 경로 어느 곳에서 열어도 정확한 섹션 URL로 이동한다.
- 새로고침 후 마지막 읽기 위치와 개인 저장 항목이 유지된다.
- 인사이트140개가 일반 문단과 구분되어 필터·저장·본문 이동이 된다.
- 본문 블록마다 원문 페이지를 찾을 수 있거나, 매핑 누락 목록에 명시된다.
- 키보드만으로 핵심 읽기와 탐색을 수행할 수 있고, 색상만으로 상태를 전달하지 않는다.
- PDF·이미지·텍스트의 사용 권한 범위 안에서만 배포하며, 기본 배포 대상은 개인 로컬 환경으로 둔다.

## 11. 착수 순서

첫 구현은 **Part 1의 한 인물 챕터 + Insight + 원문 대조**로 만든다. 이 세 요소가 완성되면 전체 콘텐츠로 확장해도 리더 구조, 교정 흐름, 시각 규칙이 흔들리지 않는다.
