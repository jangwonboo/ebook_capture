# Visual eBook 추가 기획: 주석·저장·AI 문답

기준일 2026-11-25. `기능기획.md`의 후속 문서다. 2026-11-25에 내린 결정(12장)을 반영했고, 각 기능에 구현 여부를 표시했다.

## 1. 범위와 현재 상태

| 영역 | 내용 | 상태 |
| --- | --- | --- |
| 주석 | 하이라이트 4색, 메모, 태그, 색·종류·태그 필터, 주석 검색 | 구현 |
| 저장 | 책 폴더의 `<책>.notes.json`, 자동 저장, Markdown·JSON 내보내기, JSON 가져오기 | 구현 |
| AI 문답 | 선택한 문장에 질문, 근거 문장 연결, 답을 주석으로 채택 | 구현 (실제 API 응답으로는 미검증, 13장) |
| 설정 | API 키 입력, 모델 선택, 미리 준비된 질문 편집 | 구현 |
| 끊긴 글 복원 | 쪽 경계에서 잘린 문단, 두 줄로 나뉜 제목 | 뷰어와 캡처 파이프라인 양쪽에 구현 |
| 복습 보기, 장별 질문 만들기 | 주석만 모아 크게 읽기 등 | 미구현 (10장 4단계) |

넣지 않는 것: 계정·동기화 서버, 공동 주석, AI가 본문을 요약해 원문 자리를 대신하는 화면, 뷰어에서 OCR 오탈자를 덮어쓰는 기능(파이프라인에서 처리한다).

## 2. 원칙

- 원문과 주석을 섞지 않는다. 주석은 원문 옆 패널이나 원문 위의 표시(색, 밑줄, 표식)로만 보인다.
- AI가 쓴 글은 사람이 쓴 메모와 구분해 표시하고, 근거가 된 원문 문장으로 돌아갈 수 있어야 한다.
- 주석은 책 폴더에 파일로 남는다. 브라우저 데이터를 지워도, 폴더를 다른 PC로 옮겨도 따라온다.
- 서버를 두지 않는다. 리더는 `index.html`을 여는 것으로 끝나고, AI 문답은 브라우저가 Anthropic API를 직접 부른다.
- AI를 쓰지 않아도 나머지 기능은 그대로 동작한다. 책 내용을 외부로 보내는 일은 사용자가 키를 넣고 동의한 뒤에만 일어난다.

## 3. 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html`, `styles.css` | 화면 |
| `app.js` | Markdown 파서, 목차 트리, 본문, 검색, 읽기 설정 |
| `notes.js` | 주석, 주석 파일, 내보내기·가져오기, AI 설정과 문답 |

`notes.js`는 `app.js`가 내놓는 훅(`pageRendered`, `bookOpened`, `changed`, `key`)에 붙는다. 빌드 없이 일반 `<script>`로 불러오므로 더블클릭(`file://`)으로 열린다.

## 4. 주석 모델

색만 칠한 것, 메모를 붙인 것, AI와 문답한 것이 모두 같은 레코드다.

```ts
type Annotation = {
  id: string;
  anchor: Anchor[];            // 여러 문단에 걸치면 문단별로 하나씩
  quote: string;               // 칠한 원문
  color: 'yellow' | 'green' | 'blue' | 'pink' | null;  // null이면 밑줄만
  note: string;                // 사람이 쓴 메모
  tags: string[];              // 메모 안의 #낱말에서 뽑음
  thread: Turn[];              // AI 문답
  pinned?: number;             // "주석으로 채택"한 답의 번호
  lost?: boolean;              // 원문에서 위치를 찾지 못함
  createdAt: number; updatedAt: number;
};

type Anchor = {
  node: string;                // 제목 ID
  block: number;               // 그 제목 아래 몇 번째 문단
  start: number; end: number;  // 문단 안 글자 위치
  text: string;                // 해당 구간 원문
  before: string; after: string;  // 앞뒤 20자
};

type Turn = {
  role: 'user' | 'assistant';
  text: string;
  citations?: { quote: string; node: string; block: number }[];
  model?: string;
  usage?: { input: number; cached: number; output: number };
  at: number;
};
```

이전 버전이 `localStorage`에 남긴 하이라이트는 처음 열 때 이 형식으로 옮긴다.

위치 재탐색 순서: ① 저장된 위치의 글자가 그대로면 사용, ② 같은 제목 아래에서 `text` 검색, ③ 같은 장에서 `before`+`text`+`after`, 다음으로 `text`만 검색, ④ 책 전체에서 같은 순서로 검색, ⑤ 실패하면 `lost`로 표시하고 패널에만 남긴다.

## 5. 하이라이트와 메모

### 선택 도구

```text
[● ● ● ●]  [메모]  [AI에게 묻기]  [복사]
```

- 색을 누르면 바로 칠한다. 같은 구간을 다시 고르면 새로 만들지 않고 기존 주석의 색만 바꾼다.
- "메모"는 마지막에 쓴 색으로 칠하고 패널의 메모란으로 포커스를 옮긴다.
- "AI에게 묻기"는 색 없이 밑줄만 긋고 문답 입력란을 연다.
- 칠한 부분을 누르면 색 변경, 메모, AI에게 묻기, 삭제가 뜬다.
- 단축키: `H` 칠하기, `M` 메모, `A` AI에게 묻기.

### 메모와 태그

- 메모는 주석 카드 안에서 바로 쓰고, 입력하는 대로 저장한다.
- 태그는 메모 안에 `#협상`처럼 쓴다. 별도 입력란은 없다.
- 본문 표식: 메모가 있으면 ✎, AI 문답이 있으면 ✦.

### 패널

- 범위(전체 / 이 장), 색, 종류(메모 있음 / AI 문답 있음), 태그로 거른다.
- 인용문·메모·AI 답 안에서 검색한다.
- 인용문을 누르면 본문의 그 자리로 이동해 잠깐 강조한다.
- 너비는 360px 고정이다. 1050px 이하에서는 본문 위에 겹쳐 뜬다.

## 6. 저장

### 주석 파일

```text
비트겐슈타인/
├─ 비트겐슈타인.md
├─ 비트겐슈타인.notes.json     ← 주석 원본
├─ 비트겐슈타인.notes.md       ← Markdown 내보내기 (요청 시)
└─ assets/
```

```json
{
  "version": 1,
  "book": { "title": "…", "file": "비트겐슈타인.md", "contentHash": "…" },
  "position": "제목-ID",
  "read": ["…"],
  "saved": [{ "id": "…", "createdAt": 0 }],
  "annotations": [],
  "deleted": { "주석-ID": 0 },
  "updatedAt": 0
}
```

읽던 위치, 읽음 표시, 저장한 위치도 같은 파일에 넣는다. `deleted`는 지운 주석이 다른 저장소의 옛 사본에서 되살아나지 않게 하는 기록이다.

### 쓰는 방법

| 책을 연 방법 | 주석 저장 |
| --- | --- |
| "폴더 열기" (Chrome·Edge) | 폴더를 쓰기 권한으로 열고 주석 파일에 자동 저장 |
| "파일 열기", 끌어다 놓기 | 브라우저에만 저장. 패널의 "브라우저에만 저장됨"을 누르고 책 폴더를 고르면 파일 저장으로 바뀜 |
| Firefox·Safari | 브라우저에만 저장. "JSON 내보내기"로 내려받음 |

- 변경 후 0.8초 뒤에 저장한다. 패널 머리에 "파일에 저장됨 / 저장 중… / 브라우저에만 저장됨 / 파일 저장 실패"를 보여 준다.
- `localStorage`에도 같은 내용을 항상 둔다. 책을 열 때 파일과 브라우저 사본을 주석 단위로 합치고 `updatedAt`이 최신인 쪽을 남긴다. 파일이 더 최신이면 읽던 위치, 읽음 표시, 저장한 위치도 파일 것을 쓴다.

### 내보내기·가져오기

- Markdown: 장별로 인용문, 메모, 채택한 AI 답을 묶는다. AI 답에는 "AI 답변"과 모델 이름, 날짜, 질문이 붙는다. 폴더 쓰기 권한이 있으면 책 폴더에 쓰고, 없으면 내려받는다.
- JSON: 주석 파일과 같은 형식. 가져올 때 같은 `id`는 최신 것을 남기고 위치를 다시 찾는다.

### 책이 다시 만들어졌을 때

`contentHash`가 달라지면 모든 주석의 위치를 다시 찾고 결과를 한 번 알린다. 예: "주석 42개 중 40개 확인, 2개는 찾지 못함."

## 7. AI 문답으로 주석 달기

### 흐름

1. 문장을 선택하고 "AI에게 묻기"를 누른다(또는 주석 카드의 같은 버튼).
2. 카드에 질문 입력란과 미리 준비된 질문이 열린다.
3. 답이 글자 단위로 흘러나오고, 끝나면 근거 문장이 버튼으로 달린다.
4. 이어서 물을 수 있다. 문답은 그 주석의 `thread`에 쌓인다.
5. "주석으로 채택"을 누르면 그 답이 주석의 대표 내용이 되고 내보내기에 포함된다. "메모로 복사"로 메모란에 옮겨 고쳐 쓸 수 있다.

### 미리 준비된 질문

기본값은 쉽게 풀어 줘 / 앞뒤 맥락 / 용어·인물 / 반론이다. 설정에서 `버튼 이름 | 보낼 질문` 형식으로 고치고 더한다.

### AI에게 넘기는 것

| 내용 | 위치 |
| --- | --- |
| 답변 규칙, 책 제목, 전체 목차 | 시스템 프롬프트 |
| 지금 읽는 장의 본문 전체 | 첫 메시지의 문서 블록 (인용 켬, 캐시 지점) |
| 고른 원문, 이 주석의 이전 문답, 새 질문 | 대화 메시지 |

- 범위는 "이 장"으로 고정했다. 책 전체를 넘기는 선택지는 두지 않는다.
- 답변 규칙: 문서에 근거가 있으면 인용한다. 문서 밖의 지식은 "책 밖의 설명:"으로 시작한다. 원문을 길게 옮기지 않고 서너 문단의 평문으로 쓴다. OCR 오탈자를 감안해 읽되 불확실하면 그렇다고 말한다.
- 메모와 다른 주석은 보내지 않는다.

### 근거 표시

Claude API의 인용(citations)을 쓴다. 장 본문을 평문 문서 블록으로 넣고 인용을 켜면, 답에 근거 구절과 문서 안 글자 위치가 함께 온다. 이 위치를 제목·문단 번호로 바꿔 저장하고 "근거 1 · 제목" 버튼으로 보여 준다. 누르면 본문의 그 문단으로 이동해 잠깐 강조한다. 근거가 없으면 "근거 문장 없음 (책 밖의 설명일 수 있음)"이라고 표시한다.

### 표시 규칙

- AI 답에는 "AI" 꼬리표, 모델 이름, 날짜, 입력·출력 토큰 수(캐시에서 읽은 양 포함)가 붙는다.
- 채택한 답은 배경색으로 구분한다.
- 내보낸 Markdown에서도 AI 답은 메모와 다른 블록으로 나간다.

### 동의

책마다 처음 물을 때 한 번 안내한다: 고른 문장, 지금 읽는 장의 본문 전체, 책 제목과 목차, 이 주석의 이전 문답이 Anthropic API로 전송되고, 사용료가 입력한 키의 계정에 청구된다. 동의는 책 단위로 기억한다.

### 실패 처리

실패하면 질문은 입력란에 그대로 남고 문답에는 저장하지 않는다.

| 상황 | 화면 |
| --- | --- |
| 키 없음 | 설정 창을 열고 키 입력을 안내 |
| 키가 틀림(401) | 안내와 함께 설정 창을 엶 |
| 모델 사용 권한 없음(403), 모델 없음(404) | 원인 안내 |
| 사용량 제한(429) | 다시 보낼 수 있는 시간 안내 |
| 연결 실패, SDK를 못 불러옴 | 인터넷 연결 확인 안내 |
| 모델이 답을 거절함 | "모델이 이 질문에는 답하지 않았습니다" |
| 사용자가 "중지"를 누름 | 조용히 취소 |

## 8. 설정

상단의 ⚙ 버튼으로 연다.

| 항목 | 내용 |
| --- | --- |
| Anthropic API 키 | 비밀번호 입력란. "이 브라우저에 키 저장"을 켜면 `localStorage`에, 끄면 창을 닫을 때까지 메모리에만 둔다. "저장된 키 지우기" 버튼 |
| 모델 | Claude Sonnet 5.5(기본), Claude Opus 5.5, Claude Haiku 5.5 |
| 미리 준비된 질문 | 한 줄에 하나, `버튼 이름 \| 보낼 질문` |

키는 주석 파일과 내보낸 파일에 들어가지 않는다. 다만 브라우저에 저장하면 같은 PC의 다른 로컬 HTML 파일이 읽을 수 있다(더블클릭으로 연 페이지들은 브라우저 저장소를 함께 쓴다). 설정 창에 이 점을 적어 두었다.

## 9. 기술 구조

### API 호출

- 공식 TypeScript SDK(`@anthropic-ai/sdk` 1.12.0)를 처음 물을 때 CDN에서 한 번 불러온다: `https://esm.sh/@anthropic-ai/sdk@1.12.0?bundle`. 버전을 고정했고, 여러 파일로 나뉜 빌드는 `file://`에서 20초 넘게 걸려 단일 파일 빌드를 쓴다. 20초 안에 못 불러오면 실패로 처리한다.
- 브라우저에서 직접 부르므로 `dangerouslyAllowBrowser: true`로 클라이언트를 만든다.
- 요청: `client.messages.stream`, 모델은 설정값(기본 `claude-sonnet-5-5`), `max_tokens` 64000, `output_config.effort` `medium`. 사고(thinking) 설정은 넣지 않아 모델 기본값을 따른다.
- 프롬프트 캐싱: 시스템 프롬프트와 장 본문 문서 블록이 요청마다 같고, 문서 블록 끝에 캐시 지점을 둔다. 같은 장에서 이어 묻는 동안 본문은 캐시에서 읽힌다(기본 유지 시간 5분).
- 인용: 문서 블록에 `citations: {enabled: true}`.
- 거절: `stop_reason`이 `refusal`이면 답을 저장하지 않는다. 서버 측 대체 모델(`fallbacks`)은 켜지 않았다.
- 오류는 SDK의 예외 클래스(`AuthenticationError`, `RateLimitError`, `APIConnectionError` 등)로 구분한다.

참고 단가(100만 토큰당 입력 / 출력, 2026-11-03 기준): Sonnet 5.5 $2 / $10, Opus 5.5 $4 / $20, Haiku 5.5 $0.10 / $0.50. 실제 사용량은 답마다 카드에 표시된다.

### 화면 밖 렌더링

위치 재탐색과 AI에게 넘길 장 본문은 화면에 그리지 않고 만든다. 이미지를 불러오지 않는 별도 문서에 장을 렌더링해 문단 번호를 매기고, 그 글자를 쓴다. 화면의 문단 번호와 같은 규칙이라 인용 위치와 하이라이트 위치가 서로 맞는다.

| 3 | 설정(API 키·모델·질문), AI 문답, 근거 연결, 채택, 동의, 실패 처리 | 구현 |
| 4 | 복습 보기, 장을 다 읽었을 때 칠한 문장으로 질문 만들기, 패널 너비 조절 | 미구현 |

## 11. 캡처 파이프라인 쪽 변경

OCR 결과의 교정은 뷰어가 아니라 파이프라인에서 한다. 이번에 넣은 것:

- **쪽 경계에서 잘린 문단의 띄어쓰기** (`core/seam_repair.py`, `core/paragraph_merge.py`): 쪽이 낱말 중간에서 끊겼는지("순" | "탄하지") 낱말 사이에서 끊겼는지("삶의" | "의미를")를 책 전체의 낱말 목록으로 판단한다. 이전에는 앞 조각의 끝 글자만 보고 정해서 "극단적" | "상황에서도" 같은 곳이 붙었다. 쪽 안의 줄바꿈은 기존 규칙 그대로다.
- **두 줄로 나뉜 제목** (`core/seam_repair.py`): 같은 종류의 제목 블록이 연달아 나오면 하나로 잇고, 제목 바로 앞에 떨어진 짧은 구절("마흔,", "삶에서")은 제목의 첫 줄로 붙인다. `full`·`prose` 스타일(문단 정리가 켜진 경우)에 적용한다.
- **LLM 교정 프롬프트** (`core/llm_proofread.py`): "한국어 기술서"로 한정했던 안내를 인문·교양서까지 포함하도록 넓혔다.

뷰어에도 같은 규칙이 있다. 이미 만들어 둔 Markdown을 다시 만들지 않고 읽기 위해서다. 파이프라인으로 다시 조립한 책에서는 뷰어 쪽 규칙이 할 일이 없어진다.

남은 일: LLM 교정이 쪽 단위로 돌아서, 쪽 경계에 걸친 오탈자("‘어" | "평게" → "어떻게")는 잡지 못한다. 문단을 합친 뒤에 교정을 돌리도록 순서를 바꾸는 일은 하지 않았다.

## 13. 검증한 것과 못 한 것

헤드리스 Chrome에서 `index.html`을 `file://`로 열어 확인했다.

- 확인: 기존 하이라이트 변환, 드래그 선택과 선택 도구, 메모와 태그, 필터, 키 없이 물었을 때 설정 창, 동의 창, 스트리밍 답과 근거 연결, 이어 묻기, 채택, 주석 파일 쓰기·읽기·합치기, 새로고침 뒤 복원, 틀린 키 처리, 삭제.
- AI 응답은 실제 SDK로 요청을 보내되 응답만 테스트가 대신 돌려주는 방식으로 확인했다. 요청 본문(모델, 인용, 캐시 지점, 메시지 구성)과 응답 처리는 검증됐다.
- 실제 API와는 가짜 키로 401이 돌아오는 것까지만 확인했다. `file://`에서 SDK 로딩, CORS, 키 전송이 된다는 뜻이다. 진짜 키로 답을 받아 보지는 않았다.
- 주석 파일 저장은 폴더 선택 창을 테스트가 대신하는 방식으로 확인했다. Chrome에서 실제 폴더 선택 창을 거쳐 쓰는 것은 확인하지 못했다.
- 파이프라인: `pytest` 189개 통과(기존 177개 + 새 12개). 이 책의 OCR 원본(`tmp/*.ocr.json`)이 없어 실제 책으로 다시 조립해 보지는 못했다.
